# Baseline локального хранения и истории

Дата фиксации: 8 сентября 2026.
Исходный commit: `c9db8fb50771c724ae86524a572f70a09099a85e`.

Этот файл фиксирует проверяемую исходную точку для этапа `BASE-01 / DATA-01`. Числа, требующие физического Android-планшета, намеренно не выдумываются: они должны быть добавлены после аппаратного прогона с указанием устройства и условий.

## 1. Подтверждено чтением исходников

| Область | Состояние на исходном commit | Риск |
|---|---|---|
| Документы | `BoardRepository` пишет отдельные `documents/<id>.json` через `AtomicFile` | отдельный документ атомарен, библиотека целиком — нет |
| Индекс | `documents/index.json` публикуется отдельно от документов | process death между payload и index может оставить несогласованное поколение |
| Папки | `folders.json` сохраняется отдельным вызовом после документов | документ и структура папок не имеют общей commit boundary |
| Backup | рядом с JSON поддерживаются `.bak`, legacy `boards.json` копируется при миграции | backup отдельных файлов не является транзакцией библиотеки |
| Autosave | `EditorViewModel` использует `Channel.CONFLATED` со снимком документов и папок | полезная дедупликация, но нет номера durable revision |
| Статус save | после любого завершившегося save устанавливается `saving = false` | старый ack может скрыть более новую ожидающую правку |
| Undo/Redo | два `ArrayDeque<DocumentSnapshot>`, каждый snapshot содержит `InkBoard` | память растёт пропорционально размеру всего документа на действие |
| Лимит history | 50 snapshots | фиксируется количеством, а не бюджетом памяти |
| Схема | writer пишет `schemaVersion = 2` | reader на baseline явно не запрещает будущую неизвестную схему |
| CI | PR workflow запускает `testDebugUnitTest`, `lintRelease`, `assembleRelease` | instrumentation/device tests не являются частью текущего CI |

## 2. Измерения, которые должны быть выполнены на устройстве

Контрольное устройство по `docs/ERGONOMICS.md`: Galaxy Tab S10 FE Plus + штатный S Pen. Для каждого прогона записать Android, частоту дисплея, ориентацию, размер окна, font scale, питание и температуру.

| Метрика | Baseline | Метод |
|---|---|---|
| E05, тёплое открытие N1 p95 | не измерено | 20 открытий N1 |
| E06, input → frame p95 | не измерено | trace ≥100 штрихов; физический pen-to-photon отдельно видео |
| E07, dropped frames | не измерено | 5 минут N1 с письмом/scroll/save |
| E09, durable save p95 | не измерено | pen-up → подтверждённая локальная commit sequence |
| E13, RAM/background overhead | не измерено | N2/P2 и одинаковые baseline/sync прогоны |
| E15, 90 минут | не измерено | реальная лекционная сессия |

До аппаратного прогона эти поля не считаются `pass` или `fail`.

## 3. Цель текущего изменения

1. Публиковать документы и папки одной локальной generation, а не независимыми файлами.
2. Не делать новую generation видимой до проверки всех payload и manifest.
3. Иметь предыдущую целую generation для восстановления после оборванной/повреждённой записи.
4. Ввести монотонный request sequence, чтобы старый ack не показывал ложное «сохранено».
5. Явно блокировать запись неизвестной более новой схемы документа.
6. Заменить постоянно хранимые полные snapshots Undo/Redo на операции с бюджетом 100 действий / 32 MiB; полные страницы допустимы только для структурных page-операций.
7. Сохранить legacy migration/recovery до доказанного round-trip новой схемы.

## 4. Критерии проверки этого этапа

- Старые `boards.json`, `documents/*.json`, `index.json`, `folders.json` остаются читаемыми.
- Миграция сохраняет исходные файлы до публикации новой generation.
- Две последовательные generation восстанавливают предыдущую при повреждении newest payload/manifest.
- Порядок документов после round-trip не меняется.
- Документы и папки видны только из одной опубликованной generation.
- Unknown `schemaVersion` не открывается как пустой документ и не перезаписывается.
- Обычный stroke, erase/move и OCR-object history не требуют полного `InkBoard` на каждую запись.
- Add/delete/reorder page остаются полностью обратимыми.
- `saving=false` появляется только когда подтверждён последний запрошенный локальный save либо последний save завершился ошибкой, которая видна пользователю.

## 5. Ограничения baseline

В этой среде нет физического S Pen и нельзя считать успешную JVM/CI сборку доказательством E06, palm rejection или 90-минутной стабильности. Аппаратные значения будут добавлены отдельным validation-коммитом после реального прогона; отсутствие этих чисел не подменяется оценкой по эмулятору.
