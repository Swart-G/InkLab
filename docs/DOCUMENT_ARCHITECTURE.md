# Документ, вложения и локальная сохранность

Статус: проектирование будущего этапа. Основа: [план](../INKLAB_CHANGE_PLAN.md). Реализация сейчас находится внутри `app/src/main/java/dev/swart/inklab`; перечисленные новые компоненты — предлагаемые ответственности, не существующие API.

## 2. Координаты и типы документов

Тетрадь — упорядоченная вертикальная лента страниц фиксированного размера; доска — неограниченное рабочее пространство. Они разделяют объекты, историю и OCR, но не ограничения viewport. Не притворяться, что бесконечная доска — A4 с огромным полем.

Страница хранит ID, ширину/высоту в документных единицах, origin для совместимости, фон и порядок объектов. Экранный offset, масштаб и положение ленты — состояние вида, не смещение чернил. Существующие originX/originY сохранять либо мигрировать одной проверенной трансформацией всех strokes, convertedObjects и sourceStrokes.

Цепочка преобразований: локальная точка страницы → положение страницы в ленте → viewport → координаты окна. Обратная цепочка используется при вводе, выделении и меню. При перестановке страницы меняется положение в ленте, но не координаты её объектов. Пересечение штриха с границей обрезается по существующему правилу; перенос на соседний лист не должен происходить неявно. Поворот устройства меняет только вид. Явный поворот страницы требует описанного преобразования фона и объектов и одной Undo-операции.

## 3. Фон и объектная модель

Фон каждой страницы: пустой, клетка, линейка, точки, цвет, PDF-страница, изображение, пользовательский шаблон. Параметры бумаги на документе становятся значениями по умолчанию; индивидуальная страница может их переопределить. Старые документы получают эквивалентный фон каждой страницы при миграции.

PDF-фон хранит assetId, номер исходной страницы, MediaBox/CropBox, rotation и преобразование в координаты InkLab. Изображение хранит ссылку на оригинал, crop, EXIF-нормализацию и transform. Шаблон — версия параметров/вложений; изменение шаблона не переписывает старые листы.

Общие объекты: текст, формула, изображение, фигура; позже группа. Для каждого нужны ID, bounds/transform, стиль, z-order и тип. Converted-object дополнительно хранит исходные штрихи и сведения о преобразовании. Скрытая исходная рукопись не рисуется повторно и не попадает в поиск как дубликат. Поднятие/опускание по слоям, copy/cut/paste и дублирование проходят через операции истории. Дублирование выдаёт новые ID, перемещение — сохраняет.

## 4. Импорт PDF и изображений

1. Из меню создания или меню страницы открыть системный выбор через Storage Access Framework.
2. Скопировать исходник в staging внутреннего хранилища с контролем размера, доступного места и отмены. URI провайдера не является долговечной переносимой ссылкой.
3. Проверить тип по содержимому, структуру, число страниц и геометрию. Повреждённый файл отклонить, не оставляя полутетрадь. Для защищённого PDF запросить пароль только при поддержке выбранного backend; иначе честно сообщить об ограничении. Пароль не писать в пакет или лог.
4. Показать preview первой/выбранной страницы и выбор диапазона: все либо, например, 1–8, 12, 15–20. Проверить границы и дубликаты, сохранить порядок исходника.
5. Предложить новую тетрадь или вставку до/после текущей страницы, в начало/конец. Записать страницы и asset одной транзакцией; Undo удаляет вставку, но сохраняет доступность asset для Redo.
6. Открыть первую импортированную страницу до генерации остальных thumbnails. Показать реальную фазу «Копирование/Подготовка/Готово», не выдумывать процент неизвестной длительности.

Размер PDF не приводить к A4. Сохранять исходный PDF один раз на документ, а не по копии на страницу. Аннотации InkLab независимы от оригинала. Лассо выделяет собственные объекты; извлечение области PDF позже получает отдельное действие. Изображение вставляется либо объектом с crop/rotate/resize, либо фоном новой страницы. Несколько изображений — страницы в подтверждённом порядке.

Цели: P1 готов к аннотированию p95 ≤3 с после завершения копирования; P2 ≤8 с, без предварительного рендера всех страниц. Само копирование измерять отдельно с указанием провайдера и скорости. При необходимости скорректировать бюджет через решение, а не скрывать копирование из пользовательского общего времени.

## 5. Рендер, кэши, PDF backend

Порядок: фон → штрихи → объекты → выделение → preview инструмента. Фон и экспорт используют одинаковую геометрию, но разные уровни разрешения. Миниатюры генерируются в фоне для видимых страниц; соседние страницы — ограниченная предзагрузка. Ключ кэша содержит hash asset, номер/rotation/crop страницы, параметры фона и уровень масштаба.

Рендерить текущую область, освобождать bitmap при превышении бюджета, отменять устаревшие задачи после быстрого скролла. Бюджет кэша — часть общего бюджета памяти E13; не держать по полноразмерному bitmap на каждый лист. Для большого zoom предусмотреть плитки; сначала измерить предел обычного рендера и включать их по необходимости.

До выбора backend составить таблицу: Android API 24–36, render, crop/rotation, пароль, text extraction, internal links, экспорт с сохранением вектора, лицензия и размер APK. Наличие системного renderer не доказывает наличие всех функций на минимальном API. Сохранение исходного PDF позволяет позже добавить поиск/ссылки без повторного импорта. Выбор зависимости — отдельное техническое решение на этапе реализации.

## 6. Поиск, сканы и расширения

Первый поиск по содержимому индексирует редактируемый текст/LaTeX и названия; PDF text layer добавляется после выбора backend. Индекс производный и перестраивается после restore. Результаты ссылаются на documentId/pageId/objectId или область PDF. Удалённые страницы не выдаются обычным поиском.

OCR сканов — отдельный bitmap pipeline с языком, crop и скрытым поисковым слоем, без изменения фонового изображения. OCR всего PDF не стартует автоматически. Позже: outline, внутренние ссылки с историей возврата, копирование области изображением, OCR выделенной области. Сканирование камерой: обнаружение листа, коррекция перспективы, crop, цвет/серый/чёрно-белый, предварительный просмотр, несколько страниц. Исходник сохраняется для обратимого изменения обработки.

## 7. Локальный commit и восстановление

AtomicFile защищает отдельный файл, но запись документа, индекса, папок и аудиометаданных не становится одной транзакцией автоматически. Создать единый координатор локальных commit с монотонной локальной последовательностью операций. Допустимы журнал с checkpoint или транзакционное хранилище метаданных; конкретный выбор фиксируется перед миграцией.

Операция содержит ID, документ, локальную последовательность, тип и достаточные данные применения/отмены. Записывать завершённый штрих, а не сериализовать все документы на каждую точку. UI принимает данные немедленно; durable acknowledgement приходит только после успешной записи журнала. Индикатор должен сравнивать подтверждённую последовательность с текущей: окончание старого save не снимает «Сохранение…» с более новых правок.

Checkpoint собирается в фоне во временное поколение. После проверки целостности атомарно публикуется ссылка на новое поколение. Журнал до подтверждённого checkpoint не удалять. При рестарте: валидный checkpoint → replay завершённых операций → проверка ссылок → возобновление очереди облака. Оборванный хвост журнала игнорировать с сообщением о неподтверждённом действии, не отбрасывая весь документ.

Незавершённый штрих: для MVP допускается потеря только активного, ещё не подтверждённого штриха; явно отделить его от сохранённых. Для длинного непрерывного рисования исследовать промежуточный журнал с максимальным окном 1 с. Не обещать защиту от физического отказа накопителя только на основании AtomicFile.

ENOSPC/ошибка записи: не переключать документ на пустую модель и не перезаписывать backup пустыми данными. Сохранить память, остановить рискованные операции, дать понятный путь освобождения места/экспорта. Сбой чтения одного документа не должен скрывать остальные; повреждённый элемент отображать как требующий восстановления.

## 8. История и корзина

История хранит операции: добавление/стирание stroke, изменение transform, OCR, редактирование текста, вставка/удаление/reorder страницы, смена фона. Части pixel erase группировать в один пользовательский жест. Pan/zoom и cloud upload не входят в Undo. Предлагаемый бюджет: минимум 100 обычных операций на N1 при лимите 32 МБ; при достижении бюджета удалять старейшие undo-записи, но не текущее содержимое и не backup.

Отмена создания новой страницы возвращает пользователя на ближайшую живую; отмена OCR восстанавливает точные strokes. Ссылки на вложения удерживаются пока на них ссылаются документ, корзина, undo/redo или pending snapshot.

Корзина локальная и облачная логически согласованы через tombstones. Удаление не является физическим освобождением файлов немедленно. Страницы, документы и папки имеют явные операции восстановления. Очистка корзины — отдельное действие с понятным сроком доступности облачных версий. Политика описана в sync-спецификации.

## 9. Переносимый `.inklab`

Контейнер — ZIP с manifest, данными документа, записями страниц и оригинальными assets, включая завершённое аудио. Это формат обмена/облачного snapshot, не обязательный формат активного редактирования. Не перепаковывать весь ZIP на pen-up.

Manifest описывает версию контейнера, версию схемы документа, documentId, revisionId, parentRevisionIds, deviceId, перечень файлов с размерами и SHA-256, требуемые возможности и полноту аудио. Версия в названии релиза не нужна; внутренние версии форматов обязательны для совместимости. Hash manifest хранится снаружи/в transport metadata, без самоссылочного хэша.

Включать: все страницы, strokes, sourceStrokes, text/LaTeX, реальные цвета, PDF-оригиналы, изображения, шаблоны, audio segments и метки pageId. Не включать: OAuth, секреты, диагностические логи, модели OCR, bitmap-кэши, поисковый индекс, временные файлы, device-local viewport. Папки библиотеки передаются отдельными метаданными sync; самостоятельный импорт документа может выбрать новую папку назначения.

Проверка перед импортом: допустимые относительные пути, отсутствие traversal/дубликатов/ссылок, предел распакованных байтов и количества записей, длины строк и числа точек, конечность чисел, уникальность ID, наличие всех assets, hash, ссылки pageId и отсутствие циклов папок. Начальные лимиты ручного импорта: 2 ГиБ распакованных данных и 10 000 записей; большие документы — явное решение с потоковой обработкой. Нехватка места учитывает staging и прежнюю версию. Не распаковывать поверх рабочего документа.

Три различных режима: «Импортировать копию» remap всех ID и внутренних ссылок; «Восстановить тот же документ» сохраняет ID и проверяет ревизию; «Восстановить библиотеку» предварительно показывает состав и режим объединения. Не переносить input preferences автоматически при cloud restore документа. Старый backup version 2 остаётся читаемым через свой путь миграции.

## 10. Экспорт и аудио

PDF объединяет фон, чернила, текст, формулы и изображения; скрытая исходная рукопись, selection и UI не экспортируются. Реальные цвета сохраняются независимо от ночного вида. Размер страницы соответствует документу, для доски пользователь выбирает bounds содержимого/области и масштаб. Пустая доска имеет понятный результат, а не деление на ноль.

Существующий экспорт ориентирован на A4; его нужно расширить для произвольных размеров и PDF-фона. По возможности сохранить вектор исходного PDF. Если выбранный backend позволяет только растрировать фон, это явный совместимый режим с настройкой качества и тестом печати, а не молчаливое обещание векторного экспорта. LaTeX должен визуально совпадать с редактором; OCR-оригинал не дублируется.

Экспорт страницы изображением задаёт разрешение/фон и предупреждает о слишком большом bitmap через расчёт ресурса. `.inklab` сохраняет редактируемость, PDF — результат чтения. Экспорт имеет отмену, временный выход и понятную ошибку без повреждения исходника.

Во время записи snapshot включает только завершённые сегменты, отмечая незавершённость записи. Текущий открытый m4a не копировать. После остановки собрать полную версию. MVP может ждать окончания активной записи для полного аудиоснимка, но продолжает сохранять чернила и показывает «Аудио ещё записывается». Перестановка/удаление страницы не меняет pageId меток; при удалении показать, что страница находится в корзине.

## 11. Миграции

Версии документа, контейнера и sync-протокола независимы. Не переиспользовать schemaVersion 2 для несовместимой модели. Новая схема фиксируется до записи новых файлов. Миграция: backup оригиналов → staging новой схемы → проверка геометрии, количества объектов и ссылок → атомарная публикация. При сбое открывать прежнюю версию, повторный запуск не создаёт дубликатов.

Набор совместимости: старый boards.json, текущие documents/*.json и folders.json, backup version 2 с аудио, отрицательные origin, тетради с удалёнными страницами, текст/формулы с sourceStrokes. Более новая неизвестная схема блокирует запись этого документа; показать обновление приложения или экспорт оригинального пакета. Никогда не загружать «неизвестное» как пустой документ.
